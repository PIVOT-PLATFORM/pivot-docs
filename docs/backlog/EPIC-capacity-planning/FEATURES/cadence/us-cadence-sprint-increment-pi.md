# US11.5.1 — Cadence : sprint / incrément / PI (SAFe)

**En tant que** Scrum Master / RTE
**Je veux** définir la cadence de planification — sprint, incrément (lot de sprints) ou PI SAFe (plusieurs sprints + itération IP)
**Afin de** planifier la capacité à la bonne maille agile, du sprint au Program Increment

## Critères d'acceptation

| Critère | 🤖 Dev |
|---------|--------|
| Given une équipe, when je crée une cadence, then je choisis sprint, incrément (N sprints) ou **PI SAFe** (N sprints + IP innovation/planification) | ⬜ |
| Given un incrément/PI, when je le crée, then ses sprints enfants héritent de la période et remontent leur capacité (cf. hiérarchie F11.3) | ⬜ |
| Given un PI SAFe, when on consolide, then l'itération IP est isolée (capacité non allouée au delivery par défaut) | ⬜ |

# US21.14.3 — Classification souveraineté

**En tant que** DSI/architecte
**Je veux** classer les flux de données et interdire les SaaS classe C (US sans option) pour les données sensibles, par politique outillée (DLP)
**Afin de** garantir la souveraineté des données sensibles

## Critères d'acceptation

| Critère | 🤖 Dev |
|---------|--------|
| Given les flux de données, when l'équipe SI les classe, then chaque flux reçoit une classe de souveraineté | ⬜ |
| Given un flux de données sensibles, when un SaaS classe C est envisagé, then la politique DLP l'interdit | ⬜ |
| Security/Gouvernance : l'interdiction des SaaS classe C pour données sensibles est appliquée par politique outillée, pas par circulaire | ⬜ |
